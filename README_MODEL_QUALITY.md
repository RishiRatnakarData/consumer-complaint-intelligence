# Consumer Finance Complaint Intelligence — Model Quality Add-on v0.1

**Status:** fully tested as a standalone add-on with **synthetic test data**. Not yet integrated with or verified against the existing CFPB modeling source, which was unavailable for local cloning in this session. This does not change existing model training or claims.

## Why

The published classifier reports discrimination and classification results, but the decision value of its predicted probabilities also depends on calibration and holdout threshold choices. This package adds a train-prevalence constant baseline, Brier/log loss, reliability chart, optional validation-only Platt calibration, validation-chosen raw-score operating threshold, and minimum-count-suppressed descriptive product/company diagnostics.

## PowerShell from the repository root

```powershell

```

**The demo is synthetic.** Never copy demo values onto a resume or describe these outputs as CFPB results.

## Input format — one row per unique complaint

CSV columns: `complaint_id` (recommended), `date_received` (`YYYY-MM-DD`, UTC-compatible), `split` (`train`, optional `validation`, `test`), `y_true` (0/1), `y_prob` (probability of relief, 0..1), and optional `product` and `company`. The CSV must contain at least training and test rows; training dates must precede validation dates (if present) and test dates, with no overlap. The labels MUST be true observed test outcomes; scores MUST be generated by a model trained before the scored period. Do not include narratives, names, addresses, or any customer PII.

For genuine evaluation, export predictions from your *existing classifier*. The modeling system owns its train/test split. **Do not randomly resplit the exported test data.** Preferred split: train / separate temporal calibration+threshold validation / untouched test. With only train/test available, the program performs uncalibrated model comparison using a prespecified 0.50 threshold and skips learned calibration/threshold selection.

If your current holdout is already used to choose model/hyperparameters, treat its scores as exploratory and designate a fresh later test period for a new unbiased evaluation.

## Outputs

- `model_quality.json` — dataset-size-safe metrics, data-kind provenance flag, input SHA-256 hash, date ranges, train-only prevalence constant baseline, optional Platt diagnostic, aggregate subgroup tables, notes and caveats
- `test_reliability.png` — reliability diagram from the untouched test period

Brier is a proper probability score (smaller is better); accuracy alone does not assess probability quality. The constant baseline is from training-period prevalence, never test prevalence. Calibration fits only on validation. Raw score threshold chosen on validation for a pre-specified 80% minimum recall is NOT also claimed as meeting 80% recall on test; report the actual test recall.

## Deployment and honesty

- Copy only these *new* files/directories into your repo, retaining all current source and README.
- Merge the `.gitignore.additions.txt` entries into your existing `.gitignore` by hand (do not overwrite original entries).
- Verify the old tests AND these tests on your machine. CI needs independent confirmation after GitHub push.
- Determine whether classifier export uses sample-specific rows, not all 5,442,964 aggregate-only complaint observations.
- Only present new metrics as CFPB results after creating an actual export and saving evidence.

## Model limitations

The outcome is whether the CFPB record reports monetary/non-monetary relief; it is not a causal measure of complaint merit. Product/company descriptive groups may reflect selection, case mix, imbalanced samples, and suppressed small cells. Calibration plots are binned visual diagnostics; 10-bin ECE is sample/bins dependent. Platt scaling may worsen test calibration. This package makes no automated complaint disposition recommendations.
